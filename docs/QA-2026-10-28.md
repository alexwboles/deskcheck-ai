# DeskCheck QA review — 2026-10-28

Baseline: `fa8065531fae3b78434c8472fda5e4a2a866c53c`.
All checks use synthetic files and the mock desktop. No native GUI input,
screenshots of Alex's desktop, paid services, or customer data were used.

## Reproduced and mitigated

- All 29 original tests passed, but runner and MCP input authorization trusted
  the last launched name. New focus-drift tests demonstrated click, typing and
  key actions proceeding after simulated focus moved to an unlisted app.
- Input dispatch now requires a driver target guard. Mock accepts only matching
  simulated focus; unverified/native drivers fail closed. This is a deliberate
  feature restriction, NOT completion of native isolation or a full security fix.
- The smoke script piped unittest into `tail`, allowing test failures to be
  masked by a successful pipe consumer. Unit tests now run without that pipe.

## Verified evidence

- `python -m unittest discover -s tests -q`: 36 tests pass (29 existing,
  7 regression methods, with per-input/per-native-driver subcases).
- Full `test/smoke.sh`: passed unit tests, mock CLI success and denial, and
  MCP handshake. Git Bash used a `python3` function forwarding to the installed
  Windows `python`; this is not a Linux-native acceptance run.
- Injecting a `python3` failure (exit 86) made smoke exit 86 rather than
  continuing. No real GUI driver was invoked.
- Offline wheel build succeeded using installed build tools, no dependencies
  downloaded: `deskcheck_ai-0.1.0-py3-none-any.whl`, SHA-256
  `7c104f3c93da748264f8d58b5921cbbfee1ac5f109816e8f6265c6e83e7c2b8a`.
- Installed the final wheel into a disposable review virtual environment.
  The initial `--no-deps` run failed because PyYAML was absent; installed the
  declared free PyYAML 6.0.3 dependency into that environment and retested.
  The installed console entry point (outside the source working directory)
  passed the mock demo, produced reports/screenshots, and returned exit 1 for
  the denied-app case. This is a same-PC package check, not clean-machine or
  native acceptance. The artifact is local-only, not sent to customers.
- Existing tests emit unclosed-file ResourceWarnings; these are not claimed
  fixed. No main-branch merge, customer delivery or marketing was performed.

## Release blockers / priorities

1. Native process/window identity, bounded input and focus-race containment;
   safe literal text/key handling and checked subprocess errors/timeouts.
2. App-only screenshot capture, safe output/baseline path containment, explicit
   overwrite approval, and log redaction/retention. Current native capture can
   include unrelated windows; input text is recorded in action logs.
3. Strict config and MCP validation, truthful failed-run MCP results, robust
   Ctrl-C/exception cleanup and end-to-end timeout enforcement. The browser
   throwaway flag is an operator assertion, not proof of a fresh profile.
4. Clean-machine install, native acceptance and usable delivery/onboarding.

Until these are resolved, do not advertise or sell this as a secure native
desktop test product. The free/mock developer workflow is a prototype demo,
not evidence of native runtime readiness. No payment or sale was verified.
